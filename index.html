Case Studies

Case 01 Banking Frontend Architecture Design System

From UI Fragmentation to a Shared Frontend Platform

Three banking products shared many of the same interface patterns but had no common UI foundation. Similar components were being implemented independently, creating inconsistencies and making maintenance increasingly expensive.

The same UI problems were being solved repeatedly by different parts of the team — slowing development and making changes harder to maintain.

Constraints

  • No existing shared UI foundation
  • 3 products evolving independently
  • ~5 developers, 1 designer
  • Design system built from scratch

Solution

  • Nx monorepo workspace architecture
  • 30+ shared presentation components
  • PrimeNG for interaction mechanics
  • Storybook as collaboration layer

Outcome

  • Consistent UI across 3 products
  • Faster feature development
  • Clear debugging boundaries
  • Zero business logic in UI library

Case 02 Camunda BPMN.js TypeScript

Camunda Workflow Toolkit

Our backend already relied on Camunda, but workflow management lived outside the product. I designed and built a frontend toolkit that brought BPMN editing, workflow lifecycle management, versioning, and instance monitoring into the application.

If workflows are a core capability of our product, why should users need to leave the product to manage them?

Constraints

  • Complex workflow engine
  • BPMN.js default look needed customization
  • Monitoring thousands of instances
  • API contracts owned by backend team

Solution

  • bpmn-js components integration
  • 20+ custom UI components
  • Native lifecycle and versioning UI
  • Clear frontend/backend API boundary

Outcome

  • 10+ workflows managed directly
  • Thousands of instances monitored
  • No external Camunda admin tools needed
  • Native product design integration
